# 폐기한 분기와 시행착오 기록 (Graveyard)

- ❌ [노드 core_transform / 가벼운 무상태 브리지] 폐기 이유: 현재 동반 앱은 기본 오디오/ASR, 기록, 동기화, Agent 연동을 맡는다. 무상태 전달만으로는 이 역할을 다할 수 없으며, 의미 판단은 여전히 외부 Agent에 맡긴다.
- ❌ [노드 entry_input / 휴대폰 우선 연결 게이트웨이] 폐기 이유: 두 기기가 각자 연결하도록 바꿨다. Mac은 확장/테스트, 휴대폰은 일상과 종일 기록에 중점을 두며, 기록은 확정된 동기화 경로로 교환한다.
- ❌ [노드 api_gateway / 단일 연결 노드] 폐기 이유: 기기 제어, 로컬 Agent, 기록 동기화 역할을 나눴다. 현재 기기/Agent는 loopback Bearer를 쓰고, 휴대폰 LAN 동기화는 독립 진입점과 자격 증명을 쓴다.
- ❌ [노드 speaker_channel_policy / 오프라인에서 8초 VAD로 먼저 자른 뒤 따로 군집화] 폐기 이유: 연속 맥락과 전역 소속 관계를 잃고, 짧은 구간이 버려지며, 부분 겹침이 전체 구간을 오염시켰다. 오프라인은 연속 SDK 분석으로 바꾸고 짧은 구간과 실제 교집합을 보존한다. 실시간 8초 스케줄은 따로 검증이 필요하다.
- ❌ [노드 speaker_channel_policy / 네이티브 원본 오디오를 확인 흐름이나 수동 arm에만 의존] 폐기 이유: ASR 확인 뒤 원본 오디오가 사라지고, 대기 창은 사용자의 실제 발화를 놓쳤다. 사용자 요구대로 회차마다 최신 완전 WAV를 자동 저장해 끝난 뒤 바로 비교하고, 이전 파일은 휴지통으로 보낸다.
- ❌ [노드 speaker_channel_policy / 인물 바인딩 시 익명 참조만 복사] 폐기 이유: 같은 목소리가 두 후보로 서로 경쟁해 인식이 거부되었다. 명시적 바인딩은 알려진 출처의 익명 화자를 은퇴시키고 과거 ID를 보존한다. 완전히 같은 중복 참조만 지우며, 높은 유사도만으로 사람을 자동 병합하지 않는다.
