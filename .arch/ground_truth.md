# 검증된 현실 사실과 강한 제약 (Ground Truth)

- [GT-01] (검증됨) 사용자 확인: 지금은 안경 자체의 기능을 바꿀 수 없다. OpenRayneo의 주목적은 안경에 이미 있는 공식 기능을 끌어내 2차 처리하는 것이다. -> 아키텍처 제약: 기존 공식 기능과 검증된 연결 경로를 능력의 경계로 삼는다. 동반 소프트웨어는 기능 연결, 출력 확보, 기본 2차 처리, 외부 공개를 맡는다. 안경 펌웨어를 고칠 수 있다거나, 기기 고유 기능을 추가할 수 있다거나, 확인되지 않은 공식 출력이 있다고 가정하지 않는다. 이전의 점진적 배포, 작업 관리 등의 결정은 모두 이 경계 안에서 해석한다.
- [GT-02] (검증됨) 사용자 확인: 휴대폰에 이미 Agent 소프트웨어가 있으며, OpenRayneo는 기존 방식대로 로컬 API를 노출하면 연동할 수 있다. -> 아키텍처 제약: 휴대폰 네이티브 어시스턴트는 로컬 API로 로컬 Agent와 연결한다. Agent는 대화 이해, 답변, 자체 모델이나 네트워크 서비스를 맡는다. OpenRayneo가 이를 위해 원격 Agent 실시간 연결 경로를 따로 만들 필요는 없다.
- [GT-03] 사용자가 확정된 아키텍처대로 개발하도록 승인했으며 서브에이전트에 병렬로 맡길 수 있다. 그래프의 초기 "계획만/추후 구현"은 원래 결정 단계의 설명이다. 현재 구현은 아래 스냅숏과 코드를 본다. solid는 결정이 확정되었다는 뜻이며, 빌드, 인터페이스 검증, 실제 품질은 각각 따로 기록한다. 사용자의 커밋되지 않은 작업을 보존한다.
- [GT-04] (검증됨) 사용자가 화자 처리 정책을 명확히 갱신했다: 안경 2채널 입력의 채널 1은 기본적으로 본인이며, 채널 2에만 음성 지문 매칭과 화자 분할을 한다. 종일 기록은 기본적으로 혼합 음성을 돌려주므로 완전한 혼합 오디오에 화자 처리를 해야 한다. -> 아키텍처 제약: 2채널은 반드시 두 채널을 모두 보존하고 소비한다. 본인 채널은 ASR과 고정 본인 귀속, 환경 채널은 ASR과 음성 지문/분할을 거친다. 실제 입력 모드로 종일 기록의 혼합 mono를 구분하며, 모든 mono 입력을 기본 본인으로 취급하면 안 된다. 오디오 저장, 지연 보충, 전사 출처, 시간 앵커, Agent 전달은 채널 출처와 이전 자료 호환을 유지한다.
- [GT-05] 네이티브 "샤오레이 샤오레이"(중국어 웨이크워드) 연속 대화는 로컬 Agent 대화를 재사용한다. 녹음 기록, 작업, wakeID/SID, Agent 세션 신원은 따로 관리하며 답변은 현재 회차와 대조한다. 명시적인 "새 대화"가 신원을 바꾸며, 취소는 귀속된 요청에만 영향을 준다.
- [GT-06] 사용자가 Mac이 네이티브 capture마다 최신 완전 WAV 한 회차를 자동 저장해 바로 비교에 쓰도록 명확히 요구했다. ASR 확인 흐름과 독립적이며 arm/대기 창이나 추가 60초 저장 제한이 없다. 다음 완전한 회차가 성공하면 이전 오디오는 휴지통으로 가고, 비정상 회차는 직전 유효 latest를 유지하며 captureID로 구분한다.
- [GT-07] 사용자가 `.arch/`를 프로젝트 핵심 문서로 삼고 운영 설명과 계약은 최소한만 두도록 명확히 정했다. 일반 문서는 루트 README, 운영 가이드, 핵심 프로토콜, 동기화 계약으로 모은다. 기존 사실/노드를 갱신하고 회차별 보고서와 중복 아키텍처 그림은 더 만들지 않는다. 핵심 파일 여섯 개는 메인 Git이 일반 파일로 추적하며, `.arch/.git` 섀도 저장소는 로컬에만 두고 무시한다.
- [GT-08] (2026-11-19) 사용자가 Mac 쪽은 더 검증하지 않기로 결정했다. `android-only` 브랜치는 macOS Bridge(`Sources/`, SwiftPM, 오디오 드라이버, Mac 스크립트와 CI, Mac API 스킬, 홍보 영상, Mac 전용 글꼴/아이콘/미리보기 자원)를 지우고 Android, DSH 플러그인, 프로토콜/동기화 문서, `.arch`만 남겼다. GT-06과 그래프의 Mac 노드는 `main` 이력으로만 남는다. Android 쪽 8767 동기화 서비스 코드는 바꾸지 않았고, 이 브랜치에는 Mac 클라이언트가 없다. arch-grower CLI가 로컬에 없어 graph/dashboard는 함께 갱신하지 않았다.
- [GT-09] (2026-11-19) 사용자 요청으로 `android-only`의 문서와 소스 주석/UI 문구를 한국어로 바꿨다. 기존 기록에 저장된 화자 라벨(알 수 없음/본인/혼합)과 이전 수동 지정 사유, 기억 종류는 원래 문자열을 상수로 남겨 호환을 유지하고 화면에는 한국어로 보여 준다. 실제 중국어 입력을 해석하는 코드(내비게이션 알림 파싱, CJK 문자 범위 판정)와 프로토콜 값은 그대로 둔다. `.arch/graph.json`, `dashboard.html`, `grounding.json`은 CLI 관리 대상이라 번역하지 않았다.

| 네이티브 Agent | Android 36부터 DSH 플러그인이 phone/conversation key/preset을 영구 바인딩해 웨이크를 넘어 대화 이력을 잇는다(0.1.8 SDK 격리 검사 30항목: 이력, 콜드 재시작, 취소 귀속, 실패 시 재전송 없음). 0.1.9부터 앱은 `request.context`에 음성 사실 JSON만, `input.answerMaxChars`에 표시 길이를 보내고 프롬프트는 플러그인 `voice-modes.json`(voice-three-way-5)이 소유한다(Android 자산 사본 제거). 0.1.14부터 듣기 모드 판단은 한 번의 호출로 route와 hint 답(`{route,answer}`)을 함께 받고(answer가 비면 hint를 따로 호출), 동시 처리는 6개다(이전 2개라 문장마다 오는 요청 뒤에 답이 밀려 느렸다, 실기기). agent로 간 듣기 요청은 기록 ID·기능·프리셋마다 DSH 세션 하나를 메모리에서 재사용하고, 그 세션이 다른 답을 처리 중이면 기다리지 않고 일회성 세션을 쓴다(기다리면 요청 자리를 차지해 다음 문장 판단이 막힌다). 이전에는 답마다 새 세션이었다(실기기). 실시간/종일·회의 발화는 먼저 route(wait/hint/agent, 기본 wait: 본인의 직접 질문·요청, 막힘, RayNeo 호출만 응답)를 거치며 wait는 빈 답으로 끝나 DSH 세션을 만들지 않는다. agent 메시지는 발화를 `화자: 내용`으로 한 번만 쓰고 지침은 세션 첫 턴에만 넣으며(네이티브 바인딩의 `instructed`는 프롬프트가 큐에 들어간 뒤에만 켬, 0.1.8 바인딩은 이미 받은 것으로 봄), 네이티브는 세션 이력이 있어 직전 요청/답변을 다시 넣지 않는다. 0.1.12부터 기능별 하위 폴더(`RayNeo 깨우기`, `RayNeo 실시간 답변`, `RayNeo 실시간 힌트`, `RayNeo 종일 기록`, `RayNeo 작업`)를 DSH `workspaceRegistry`에 작업 공간으로 등록하고 `session.create({workspaceId})`로 만든다. DSH는 작업 공간을 첫 실행 부트스트랩과 명시 등록으로만 만들므로 cwd만 주는 것에 기대지 않는다. 실기기에서 0.1.11 폴더가 없던 것은 플러그인 교체 뒤 엔진을 재시작하지 않아 옛 코드가 돌던 탓이었다(DeepSeek가 휴대폰에서 확인: 세션 cwd `/root`, 엔진 시작 시각이 교체 이전). 플러그인 교체 뒤에는 반드시 엔진을 재시작한다. 폴더 이름은 알려진 기능만 쓰고 나머지는 `RayNeo 작업`(0.1.13). 휴대폰에서 DeepSeek가 직접 만든 같은 번호 0.1.12(모드별 `직접깨움` 등, cwd만 사용)는 0.1.13이 대체한다. 레지스트리가 없거나 등록이 실패하면 cwd로 만든다. 네이티브 바인딩 키에 'workspace'를 더해 0.1.11 바인딩과 분리한다. 상위 폴더는 설정 `sessionFolder`(0.1.15부터 빈 값도 `OpenRayneo`, 상대 경로는 홈 기준, `~`/절대 경로 가능. 0.1.14까지는 상대 경로가 엔진 작업 폴더 기준이고 빈 값이면 폴더 없이 DSH 기본이라, 실기기 깨우기에서도 폴더가 생기지 않았다: 저장된 설정이 비었거나 엔진이 옛 코드였을 가능성, 미확정)를 `session.create({cwd})`로 받아 DSH에서 한 폴더로 묶인다. 폴더는 처음 쓸 때 만들고, 만들 수 없으면 경고 후 DSH 기본 폴더를 쓰고 그 네이티브 세션은 바인딩하지 않는다. 폴더를 지정하면 네이티브 바인딩 키에 입력한 설정값이 들어가 새 폴더에서 새 대화가 시작된다. 판단 품질은 실기기 확인 필요. |
| 휴대폰 ASR | `asrEngine` 선택: 클라우드 Bailian은 쓰임새별 모델이다. 문장 끝이 LLM으로 넘기는 시점이므로 깨우기(NATIVE)는 짧은 입력용 `qwen-audio-3.1-asr-flash-message`(발화 전체 보정, `intermediate_result_enabled`·`disfluency_removal_enabled`를 켬, 설정 `asrModelWake`), 실시간 답변·힌트(REALTIME)와 자막·번역은 `qwen-audio-3.1-asr-flash-streaming`(실시간 권장 모델, 같은 run-task duplex, `max_sentence_silence` 700ms), 종일·회의 등 기록은 같은 streaming에 1200ms(설정 `asrModelLive`)를 쓴다. streaming에는 문서에 없는 짧은 입력용 매개변수를 보내지 않는다. 기본 streaming이 시작 전에 모델·매개변수 오류 코드로 거부되면(키·잔액·제한 오류는 제외) 앱 재시작 전까지 계속 듣기도 `-message`로 돌아간다. 이전 단일 설정 `asrModel`은 더 읽지 않는다. 국제 `dashscope-intl` 엔드포인트에서 streaming 동작은 실기기 확인 필요(기본 주소는 국제 `wss://dashscope-intl.aliyuncs.com/api-ws/v1/inference`: 국제 계정 키로 본토 주소를 쓰면 인식이 실패한다는 것을 실기기에서 확인, 요약·번역 기본 모델은 `qwen3.7-flash`(싱가포르 기준 32K 이하 입력 0.03/출력 0.13달러/100만 토큰, qwen-plus는 0.4/1.2), 중간 결과, `disfluency_removal_enabled`, `vad_model=near_meeting_16k`. 네이티브 웨이크는 중간 결과를 0x0d type5 `final:false`로 안경에 보냄). 실기기 로그: 답변 뒤 안경은 재생이 끝날 때 type11로 다음 턴을 연다. 예전 흐름은 답변 전에 2 rc2로 수음을 닫아서 답변 중 말해도 소용이 없었다. 지금은 안경 workMode=1(연결 시 설정 자동 조회)이면 수음을 닫지 않고 답변 직후 다음 턴을 연다(2 rc1만 보내고 9 rc1은 보내지 않음). 답변 중 네이티브 마이크(48k)의 10ms 레벨이 `bargeInLevelDb`(기본 -30dBFS)를 `bargeInMinMs`(기본 250ms) 이상 연속으로 넘으면 바로 9 rc1로 끊는다(ASR을 기다리지 않음). 첫 중간/최종 텍스트(2글자 이상이고 답변 텍스트에 없는 것)도 끊는다. 답변 중 최대 레벨을 로그에 남겨 보정에 쓰며, 끊지 않으면 type11을 기다려 9 rc1을 보낸다. `nemotron`=Nemotron 3.5 다국어 스트리밍 0.6B 560ms int8(sherpa≥1.13.3, stream option `language`: 힌트가 하나면 ko-KR/en-US, 아니면 auto. 4스레드. 앱 안에서 HF 서드파티 미러로 받으며 공식은 tar.bz2뿐). 로컬 모델은 사용자가 | 안경 내장 기능 | 안경 메뉴 기능은 안경이 화면을 그리고 휴대폰이 오디오를 받아 결과를 돌려준다. 공식 1.0.25 종류표: `0x13/0x17` type 1 시작 요청, 2 시작 결과+설정, 3 종료, 4 오디오, 5 텍스트, 6 재시도, 7/8 설정 요청/응답, 9 요청 수신 확인(`confirm_type`, 0x01을 받은 쪽이 보냄), 0x0A 서비스 설정, 0x0B 상태 동기화(`state` idle/paused…), 0x0C 다화자 텍스트. **Live captions(`0x13`)**: 실기기 확인 — 안경 type1 `{sid,trigger:2,code:1,settings:{mode:"classic",source_language:"en-US",target_language:"zh-CN",…}}`에 같은 sid로 type2 `{sid,code:1,final_settings}`를 보내면 이어받아 ASR 자막이 표시된다. 기록 요약 모델이 설정되어 있으면 한↔영 번역을 하고(final_settings 언어는 ko-KR→en-US로 표시), 없으면 전사만 한다. 안경 자막 페이지는 status1을 줄로 쌓고 status0은 열린 줄을 바꾼다. mode 3은 전사 전용이라 `target_translation`을 무시하고, mode 1(classic)은 번역을 받지만 줄이 쌓이고 고개를 들면 원문, 숙이면 번역이 보여(실기기) 읽기 어렵다. 그래서 모든 화면을 mode 3 status0 한 덩어리(약 100자, 한글 한 화면)로 보내 매번 교체한다: 위 줄은 최신 번역(앞 64자, 전사만 할 때는 직전에 끝난 문장), 아래 줄은 지금 말하는 원문 끝부분이다. 원문만 보이고 번역이 4초 뒤 사라지던 이전 방식(원문 위, 번역 아래, 말하는 중 원문만)은 실기기에서 영어만 흐르는 것처럼 보였다. 끝난 문장은 최대 3개를 동시에 번역하고 순서대로 표시하며, 말하는 중에도 구두점, 60자 증가, 3초 경과마다 한 번에 하나씩 미리 번역해 위 줄을 갱신한다(그 문장이 끝나면 버림). Model Studio(dashscope) 주소의 일반 Qwen 모델에는 `enable_thinking:false`를 보내고(thinking 전용 모델 제외), 번역 요청은 12초에 끊어 한 문장이 뒤 문장을 오래 막지 않게 한다. 로컬 휴대폰 모델은 한↔영 품질과 지연이 클라우드 flash보다 나을 근거가 없어 쓰지 않는다. **Live answers(`0x17`)**: 실시간 힌트 기록으로 이어받되 DSH에 `mode: live_answers`를 보낸다. 플러그인 0.1.16부터 기록마다 DSH 세션 하나에 들린 문장을 모두 이어 넣고(분류 호출 없음), 세션이 대화 전체 흐름으로 힌트가 필요한 순간을 판단해 답하거나 `PASS`(빈 답)를 낸다(지침 `live_answers_session`). 한 번에 한 턴만 돌고 그사이 들린 문장은 다음 턴에 함께 들어가며, 기다리는 요청은 최신 하나만 남고 나머지는 바로 빈 답으로 끝난다. 이전(0.1.15까지)에는 문장마다 최근 몇 줄만 보고 따로 분류해 대화 전체 맥락이 없었고 질문이 분명할 때만 답했다(실기기 지적). 이어받지만 안경 화면이 계속 로딩 상태다(원인 미확정, 세션 안의 안경 비오디오 신호를 처음 10개까지 로그). 듣기 화면(실시간 힌트·Live answers)은 자막처럼 들리는 말을 모두 전사한다: REALTIME 기록의 채널별 중간 결과와 최근 끝난 문장 4개를 이어 위 줄(답이 없으면 끝부분 90자, 답이 있으면 30자)에, 답은 그 아래에 둔다. 답은 화면을 바꾸지 않고 듣기 화면에 붙으며 80자 페이지로 7초마다 넘기고 마지막 페이지 뒤 `answerClearSeconds`(0이면 15초)가 지나면 지운다(다른 화면이 앞에 있으면 멈춤). 들은 문장마다 DSH 요청이 나가고 대부분 wait로 끝나므로, 답은 더 최신 답이 이미 표시됐거나 듣기 화면이 다시 열린 경우에만 버린다. 이전 방식(답이 오면 답 화면으로 전환)은 다음 문장에 답이 버려지거나 답 화면에 머물러 이후 인식 결과가 안 보였다(실기기). 안경 답변 창은 약 120자가 넘으면 아래 줄이 잘려서, 긴 답변은 80자 안팎 페이지로 나눠 " (i/n)"을 붙이고 7초마다 넘기며 질문 줄은 30자로 줄인다. **Voice memo(`0x0e`)**: 실기기 확인 — 안경이 type1 action1 `{uuid,mode:1,code:1,sid,type:1}`를 보내고 응답이 없으면 3초 뒤 code 25로 다시 보내며 오류를 띄운다. 이제 type1 action2 `{uuid,type:1,mode,code:1,action:2,sid}`로 답하고(예전 Mac 구현과 같은 모양), 일시정지/재개/모드/마크/상태/정지 요청에도 action2로 답한다. 240바이트 Opus(type3, offset 기준)를 모노 16kHz 암호화 오디오로 저장해 `VOICE_MEMO` 기록으로 남기고, 저장 오디오 보충 경로로 나중에 전사한다(Agent에는 보내지 않음, Live captions 중에는 보충을 미룸). 안경 메뉴 요청은 실시간 힌트·번역·다른 화면이 쓰는 중일 때만 거절하고, 음성 깨우기/종일 기록/음성 ### 수정 후 확인된 문제와 후속 수정

**R12 · P1 · 수정됨(코드) · 손상 기록 제외 후 동기화 시퀀스 후퇴.** **수정:** 발급한 최고 sequence를 기록과 별도인 `sequence-mark`(AtomicFile)에 데이터 파일보다 먼저 쓰고, 시작 시 읽을 수 있는 기록의 최대값과 표식 중 큰 값을 쓴다. 표식이 없거나 손상된 상태에서 읽을 수 없는 기록이 있으면 현재 시각(ms)으로 건너뛴다. [동기화 계약](../docs/record-sync-contract.md)에 반영. 실기기 손상 재현은 남아 있다. 원래 지적: `ConversationRepository.kt:26–32`는 읽을 수 없는 기록을 제외한 뒤 남은 records/people의 최대값으로 `sequence`를 다시 만든다. `81,127–128`은 이 값을 증가시켜 저장하고 클라이언트 cursor보다 큰 값만 내보낸다. 예를 들어 클라이언트가 cursor=100까지 받은 뒤 sequence=100의 기록이 손상되고, 정상 객체 최대가 10이면 재시작 후 새 기록은 11부터 저장된다. 해당 클라이언트는 100을 넘을 때까지 새 기록을 받지 못하며 중간 객체는 이후 수정하지 않으면 계속 누락될 수 있다. 기존 서비스 시작 실패는 완화됐지만 동기화 계약의 영구 단조 증가 조건은 깨질 수 있다. 기록과 독립된 영구 high-water mark 또는 명시적 epoch/전체 재동기화 절차가 필요하다. 개발용 복제 데이터에서 최고 sequence 기록만 손상시킨 뒤 기존 cursor로 새 기록이 도착하는지 확인해야 한다. 이번에는 암호화 사용자 기록을 손상시키거나 실제 동기화 장애를 유발하지 않았다.

**R13 · P2 · 수정됨(코드) · 엔진 외 음성 설정의 표시/저장 불일치.** **수정:** 상주 모델, 언어 힌트, 자동 응답, 음성 게이트, 자동 요약 체크박스가 모두 `formDrafts`를 직접 읽는다. 기본값 의미(없음=켜짐/자동 응답은 꺼짐)는 그대로다. 원래 지적: `VoiceSettingsScreen.kt:65–91,107–108`의 상주 모델, 언어 선택, 자동 응답, 음성 게이트, 자동 요약은 여전히 `remember(model.config)`로 표시 상태를 만들고 변경 시 `formDrafts`에도 쓴다. 엔진 라디오만 초안을 직접 읽도록 바뀌었다. 예: 저장된 자동 응답=false → 켬 → 저장 없이 이탈/재진입하면 화면은 꺼짐, 초안은 true → 저장하면 자동 응답이 켜질 수 있다. 언어·게이트도 같은 경로다. 모든 해당 컨트롤을 초안에서 직접 읽도록 통일하고 미저장 이탈/재진입/회전 후 표시와 저장값을 대조해야 한다. 실제 기기 검증은 남아 있다.

### 검사 중 장애와 복구 기록

- 최초 Windows `gradlew.bat --version`은 Java 부재로 실패했다. WSL에 이미 설치된 JDK/SDK를 찾아 사용했으며 시스템 Java를 새로 설치하지 않았다.
- 최초 소스 archive는 Windows 줄바꿈 설정으로 shell 스크립트가 CRLF가 되어 실행되지 않았고, WSL 명령 전달 중 PATH/변수 인용 문제도 있었다. `git -c core.autocrlf=false archive`로 기준 커밋을 다시 내보내고 고정 Linux PATH와 직접 인자를 사용하여 해결했다. 저장소의 원래 Git blob은 LF였으며 앱 소스 결함으로 분류하지 않았다. APK 서명 검사도 초기 인자 전달 실패 후 명시적 경로로 재실행해 통과했다.
- 최초 `npm pack --dry-run`은 저장소 루트에서 실행하여 package.json 부재로 실패했다. 플러그인 폴더에서 다시 실행해 dry-run과 실제 pack 모두 통과했다.
- `npm ci` 실패는 실제 잠금 파일 문제로 남겼다. 추가 모듈 검사를 위해서만 Temp 복사본에 잠금 파일을 쓰지 않는 설치를 수행했다. 원본 package/lock은 변경하지 않았다.
- `.agents/skills/` 잔여 디렉터리에는 접근 거부가 있어 Git/파일 탐색 경고가 나왔다. 현재 Android 전용 HEAD에는 Mac API 스킬이 없으며, 권한 변경/강제 삭제 없이 검사했다.
- 검증에 필요한 Gradle/모델/npm 의존성을 캐시에 내려받았고 ADB 조회가 로컬 ADB 서버를 시작했다. 사용자 모델·녹음·기기 설정을 열거나 바꾸지 않았다.
